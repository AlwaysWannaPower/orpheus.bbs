# 📚 Учебные материалы

Эта папка — **вторая половина проекта**. Код в `src/` объясняет *как* всё
устроено (в комментариях), а эти файлы объясняют *почему* — и дают базу,
которой у кода нет места вместить.

Материалы написаны для человека, который **учит фронтенд с нуля**, но при этом
взрослый специалист в данных (SQL, ClickHouse, dbt, BI). Поэтому аналогии с
миром данных встречаются часто и намеренно.

## Быстрый маршрут: «хочу понять проект за вечер»

1. [`01-roadmap.md`](01-roadmap.md) — общая картина.
2. [`09-struktura-proekta.md`](09-struktura-proekta.md) — где что лежит и как
   данные идут от файла на диске до кнопки в браузере.
3. Открыть в редакторе `src/lib/types.ts` → `src/lib/db/schema.ts` →
   `src/lib/scanner/index.ts` → `src/app/api/tracks/[id]/stream/route.ts` →
   `src/components/player/player-context.tsx` и читать **вместе с главами 03,
   05, 06**.
4. Дальше — по любой главе, которая зацепила.

## Медленный маршрут: «хочу реально выучить стек»

1. 02 → 03 → 04 подряд, не пропуская: это фундамент.
2. После каждой главы — залезть в код и найти там то, о чём прочитал.
3. Поменять что-нибудь маленькое и посмотреть, что сломалось.
   Сломать и починить — самый быстрый способ понять.
4. 05 → 06 → 07 — «инженерная» часть: HTTP, SQL, ORM.
5. 08 — про медиа в браузере.
6. В конце — 10 (Docker) и 13 (что дальше).

## Принципы этих материалов

* **Русский язык, обращения на «ты».** Это личная тетрадь, а не документация
  для внешних читателей.
* **Примеры — из этого проекта.** С указанием реальных файлов, а не выдуманные
  `foo`/`bar`.
* **Сначала «зачем», потом «как».** Знание синтаксиса бесполезно без понимания,
  какую задачу он решает.
* **Честно о подводных камнях.** Где были ошибки при разработке — там об этом
  написано. Ошибка, о которой предупредили заранее, стоит десять прочитанных
  глав.
