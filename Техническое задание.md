## 🎵 Проект: Personal Music Player

Идея простая:

> Я запускаю Docker на любом компьютере → указываю папку с музыкой → открываю браузер → вижу свою библиотеку → слушаю музыку.

Примерно так:

```text
                    ┌─────────────────────┐
                    │      Browser        │
                    │                     │
                    │   🎵 Music Player   │
                    │                     │
                    │  Albums / Artists    │
                    │  Search / Playlists │
                    │                     │
                    │  ───────●──────     │
                    │  ◀  ▶  ⏭    🔊     │
                    └──────────┬──────────┘
                               │
                            Next.js
                               │
                 ┌─────────────┴─────────────┐
                 │                           │
             SQLite                     /music
                 │                           │
          информация о                   mp3/flac
           композициях                    файлы
```

# Этап 1. Самый первый плеер

Вообще без базы.

```text

├── public/
├── package.json
```

Запускаем Next.js через Bun.

```text
│       ◀     ▶     ▶│                    │
│                                         │
```

На этом этапе задача только одна:

# Этап 2. Подключаем реальные файлы

Вот тут появляется Next.js backend.

Например, на компьютере:

```text
~/Music/
├── Linkin Park/
│   ├── Numb.mp3
│   └── In The End.mp3
│
├── Daft Punk/
│   ├── Get Lucky.mp3
│   └── One More Time.mp3
│
└── ...
```

Приложение получает доступ к этой папке.

Например:

```text
/music
```

будет смонтирована в Docker.

```text
Docker
│
└── Next.js
       │
       └── /music
             │
             ├── Numb.mp3
             ├── ...
```

И Next.js сможет отдавать аудио браузеру.

# Этап 3. Нормальный streaming

Здесь мы делаем уже не просто:

> "вот тебе MP3-файл"

а настоящий streaming endpoint.

Например:

```text
GET /api/tracks/123/stream
```

Браузер говорит:

```text
Мне нужны байты 0–1 000 000
```

потом:

```text
Мне нужны байты 1 000 000–2 000 000
```

Это позволит нормально:

* перематывать;
* начинать проигрывание до полной загрузки;
* работать с большими файлами.

И здесь ты познакомишься с одной из реально интересных частей HTTP.

# Этап 4. SQLite

Вот здесь появляется твоя идея с "картотекой".

Да, **SQLite тебе вполне подходит**.

Но не надо делать огромную БД.

Например:

```text
tracks

id
path
filename
title
artist
album
duration
created_at
```

И, например:

```text
playlists

id
name
created_at
```

и:

```text
playlist_tracks

playlist_id
track_id
position
```

Всё.

# Этап 5. Сканер музыки

Это будет одна из главных частей приложения.

Ты кладёшь:

```text
/music

    Artist A/
        Song 1.mp3
        Song 2.mp3

    Artist B/
        Song 3.mp3
```

Нажимаешь:

```text
SCAN LIBRARY
```

Программа:

```text
        /music
           │
           ▼
       ищем файлы
           │
           ▼
      *.mp3 / *.flac
           │
           ▼
      читаем metadata
           │
           ▼
       SQLite
```

Получается:

```text
Filesystem = реальные файлы

SQLite = индекс этих файлов
```

Это очень хорошая модель для такого приложения.

# Этап 6. Metadata

Вот здесь становится интересно.

У MP3 может быть встроена информация:

```text
Title: Numb
Artist: Linkin Park
Album: Meteora
Year: 2003
```

Программа её читает.

Если metadata нет:

```text
Numb.mp3
```

можно использовать:

```text
title = "Numb"
artist = "Unknown"
```

То есть **тебе не придётся вручную создавать карточки для 500 песен**.

# Этап 10. Docker

**Только после того, как приложение нормально работает локально.**

Делаем:

```text
docker compose up -d
```

И получаем:

```text
http://localhost:3000
```

При этом:

```text
Host
│
├── music/
│     ├── song1.mp3
│     ├── song2.mp3
│     └── ...
│
└── Docker
      └── music-player
```

SQLite тоже желательно хранить через volume:

```text
Host
│
├── music/
└── data/
      └── music.db
```

Тогда удалил контейнер → **музыка и библиотека не пропали**.

# А YouTube?

Я бы пока **вообще не смешивал его с плеером**.

Сначала:

```text
MP3 → положил в папку → плеер увидел
```

А потом отдельная функция:

```text
YouTube URL
     ↓
Downloader
     ↓
audio file
     ↓
/music
     ↓
Scan
     ↓
Library
```

И тогда downloader становится просто **источником новых файлов**.

При этом использовать его стоит для контента, который тебе разрешено скачивать, с учётом условий YouTube и прав правообладателей.
