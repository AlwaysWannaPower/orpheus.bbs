# 12. Дизайн и темы: античность × хакеры 90-х

Эта глава — про визуальную часть проекта и **задел на сайт-резюме**, который
ты планируешь делать позже. Разбирается не «список цветов», а устройство
дизайн-системы: почему она устроена именно так, как добавлять свои темы и как
перенести стиль в другой проект.

---

## 1. Идея оформления

Задача была сформулирована так: **гибрид древнегреческой культуры и хакерской
культуры девяностых**.

Что взято от каждой стороны:

| От греческой античности | От хакеров 90-х |
| --- | --- |
| Цвет: мрамор, золото, терракота, цвет ночного моря | Форма: моноширинный шрифт, капс, ASCII-рамки |
| Орнамент: меандр (греческий ключ), дорический фриз | ЭЛТ-монитор: полосы развёртки, виньетка, свечение |
| Название: ΟΡΦΕΥΣ, подписи тем греческими буквами | Мигающий курсор, тексты вида «[ СКАН ЗАВЕРШЁН ]» |
| Архитектура: уголки панелей как акротерии фронтона | Табличный список треков, счётчики, «терминальные» кнопки |

Ключевая мысль: **греческое — в цвете и орнаменте, хакерское — в форме
и поведении.** Если сделать наоборот (зелёный фосфор плюс греческие завитушки
всюду), получится каша.

### Откуда взялось имя

**ΟΡΦΕΥΣ** (Орфей) — мифический певец, чья музыка укрощала зверей, деревья
и подземных богов. Идеальный покровитель музыкального плеера. Плюс он
спускался в подземный мир — а в хакерской культуре это читается как «работа
на нижнем уровне системы».

**.BBS** — Bulletin Board System, электронные доски объявлений, на которых
держалась вся досетевая хакерская культура конца 80-х и 90-х. Именно оттуда
родом эстетика фильма «Хакеры» (1995).

Имя и все связанные с ним строки живут в **одном файле** —
`src/config/branding.ts`. Переименовать проект = поправить одну строку.

## 2. Три темы

Оформление не одно — их три, и они переключаются прямо в интерфейсе
(боковая панель, раздел «ΘΕΜΑ · ТЕМА»).

| id | Название | Идея |
| --- | --- | --- |
| `aegean` | **Эгейское море** (по умолчанию) | Мрамор, золото и ночная синева. Античный храм в терминале. |
| `oracle` | **Дельфийский оракул** | Янтарный монохром. Отсылка и к пифии в дыму, и к первым монохромным мониторам — они были именно янтарными, а не зелёными. |
| `gibson` | **Гибсон** | Фосфорно-зелёный CRT. Прямая цитата из фильма «Хакеры» 1995 года. |
| `alexandria` | **Александрийская библиотека** | **Светлая** тема: папирус и чернила. ЭЛТ-эффекты выключены, углы скруглены. |

По умолчанию — `aegean`. Почему: первая версия оформления была целиком
зелёной, и это оказалось неудобно (см. следующий раздел). «Гибсон» остался
как режим «для настроения».

## 3. Проблема первой версии: всё зелёное

Первое оформление было выдержано в одном цвете — фосфорно-зелёном.
Пользователь сразу сказал: «слишком зелёный» и, что важнее, **«текст не везде
хорошо видно, раздел с хоткеями почти сливается»**.

Это не придирка, а системная ошибка, и стоит разобрать её по частям.

### Ошибка 1: один цвет на все роли

Зелёный использовался одновременно как:

* основной текст,
* второстепенный текст,
* заголовки,
* рамки,
* акценты,
* фон.

Когда всё одного цвета, глаз **не понимает, что важно**. Это нарушение
визуальной иерархии.

**Лечение:** роли развели жёстко.

| Роль | Что делает | Как выглядит теперь |
| --- | --- | --- |
| `ink` | читать | мрамор (светлый) |
| `accent` | нажимать | золото |
| `line` | обрамлять | тёмно-синий |
| `canvas` | уходить на второй план | почти чёрный |

### Ошибка 2: цвет рамки использовался для текста

Подсказка по горячим клавишам была окрашена в `acid-dark` — самый тёмный
оттенок палитры, предназначенный для **рамок**. Посчитаем контраст по формуле
WCAG 2.1:

```
было:  #0a2a12 на #040704  →  1.30 : 1     ❌
```

Норма WCAG AA для обычного текста — **4.5:1**. То есть текст был не «немного
бледным», а практически невидимым.

Стало (все три темы):

```
aegean:  ink 16.71:1 · ink-muted 9.58:1 · ink-faint 5.76:1   ✅
oracle:  ink 14.92:1 · ink-muted 9.64:1 · ink-faint 5.73:1   ✅
gibson:  ink 18.08:1 · ink-muted 12.27:1 · ink-faint 7.17:1  ✅
```

### Ошибка 3: контраст проверялся «на глаз»

Именно поэтому ошибка №2 и проскочила. Глаз привыкает к монитору и перестаёт
замечать, что текст на грани различимости. Контраст надо **считать**.

Маленький скрипт для проверки (работает через `bun -e`):

```js
const lum = (h) => {
  const [r, g, b] = [1, 3, 5].map((i) => {
    const c = parseInt(h.slice(i, i + 2), 16) / 255;
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
};
const ratio = (a, b) => {
  const [hi, lo] = [lum(a), lum(b)].sort((x, y) => y - x);
  return ((hi + 0.05) / (lo + 0.05)).toFixed(2);
};

console.log("текст к фону:", ratio("#f2ece0", "#080b14"));   // aegean
console.log("проверка для любой своей темы…");
```

**Вывод, который стоит запомнить:** любой цвет текста проверяй расчётом.
Это две минуты работы и целый класс проблем, которых больше не будет.

### Насколько «другим» может быть дизайн

Закономерный вопрос: если тема — это набор переменных, то можно ли сделать
оформление, **не похожее вообще ни на что**? Ответ: да, но глубина
изменений ограничена тем, какие параметры вынесены в контракт темы.

Полезно различать три уровня «другости»:

| Уровень | Что меняется | Требует правки компонентов? |
| --- | --- | --- |
| **1. Палитра** | цвета, тени, прозрачности | нет |
| **2. Форма и декор** | скругления, плотность ЭЛТ, свечение, орнаменты | нет |
| **3. Раскладка** | расположение блоков, другой набор элементов | **да** |

Уровни 1 и 2 в проекте реализованы полностью: темы задают не только цвета,
но и радиусы, плотность полос развёртки, силу свечения и прозрачность
орнаментов.

**Доказательство — тема `alexandria`.** Она светлая (папирус и чернила),
без ЭЛТ-эффектов, со скруглёнными углами и без свечения. Это не «другой
оттенок», это другой интерфейс. И ни один React-компонент для этого
не менялся — только один CSS-файл.

Уровень 3 (другая раскладка) переменными не решается: положение блоков
задано в JSX. Но и это возможно — двумя способами:

* **переключать компоненты раскладки** по id темы (`const Shell = theme.layout === "sidebar" ? SidebarShell : TopbarShell`);
* **менять местами области через CSS Grid** — например, `grid-template-areas`
  в переменной темы, тогда один и тот же JSX раскладывается по-разному.

Для личного проекта уровня 1–2 более чем достаточно. Если однажды захочется
уровня 3 — теперь понятно, с какой стороны к нему подходить.

## 4. Архитектура: роли вместо цветов

Это главное техническое решение главы.

### Как было бы «по-простому»

```tsx
// ❌ Цвет зашит прямо в компонент
<div className="text-[#e8b53f] bg-[#0e1422] border-[#2b3550]">
```

Работает. Но: поменять палитру невозможно без поиска-замены по всему проекту.
А уж сделать три темы — тем более.

### Как сделано

Компоненты говорят **ролями**, а конкретные цвета подставляет тема:

```tsx
// ✅ Указана роль, цвет придёт из темы
<div className="text-accent bg-surface border-line">
```

Цепочка получается такая:

```
утилита Tailwind          .text-accent { color: var(--color-accent) }
        │
        ▼
CSS-переменная            --color-accent: #e8b53f
        │
        ▼
значение из темы          html[data-theme="aegean"] { --color-accent: #e8b53f }
                          html[data-theme="gibson"] { --color-accent: #00ff41 }
```

Меняем один атрибут на `<html>` — меняется оформление всего приложения.
**Ни один React-компонент при этом не перерисовывается.**

### Полный набор ролей

| Токен | Роль | Группа |
| --- | --- | --- |
| `canvas` | фон страницы | фон |
| `surface` | фон панелей | фон |
| `surface-2` | вложенные блоки, дорожки ползунков | фон |
| `ink` | основной текст | **текст** |
| `ink-muted` | второстепенный текст, подписи | **текст** |
| `ink-faint` | служебный текст: нумерация, подсказки | **текст** |
| `line` | обычные рамки | рамки |
| `line-strong` | заметные рамки | рамки |
| `accent` | главное действие | акцент |
| `accent-2` | предупреждение, важное | акцент |
| `accent-3` | ссылки, служебные акценты | акцент |
| `alert` | ошибки, удаление | акцент |
| `on-accent` | текст поверх акцентного фона | инверсия |

**Правило, которое нельзя нарушать:** цвета группы «рамки» — только для
`border-*`. Никогда для текста. Для текста есть три уровня `ink`, и даже
самый бледный обязан проходить 4.5:1.

## 5. Технически: как это собрано в Tailwind v4

### Объявление токенов

```css
/* src/app/globals.css */
@import "tailwindcss";

@theme {
  --color-ink: #f2ece0;
  --color-accent: #e8b53f;
  /* … */
}
```

Блок `@theme` — новинка четвёртой версии. Всё, что там объявлено:

1. становится **CSS-переменной** (`--color-ink`);
2. **автоматически порождает утилиты** (`text-ink`, `bg-ink`, `border-ink`).

Раньше токены настраивались в JavaScript-файле `tailwind.config.js`.
Теперь всё живёт в CSS — ближе к платформе и проще для понимания.

### Значения приходят из тем

```css
/* src/themes/gibson.css — отдельный файл, подключён через @import */
html[data-theme="gibson"] {
  --color-ink: #c9ffd6;
  --color-accent: #00ff41;
  /* … */
}
```

Почему это работает, хотя `@theme` объявляет `:root`:

* `:root` — это селектор `html` со специфичностью (0,1,0);
* `html[data-theme="gibson"]` — тег плюс атрибут, специфичность (0,1,1).

Второй селектор **специфичнее**, поэтому побеждает. А поскольку утилиты
ссылаются на `var(--color-ink)`, а не на само значение, они автоматически
подхватывают новое.

### Три темы — три файла

```
src/themes/
├── registry.ts     метаданные: id, название, описание, цвета для превью
├── aegean.css
├── oracle.css
├── gibson.css
└── README.md       инструкция «как добавить свою тему»
```

Разделение важное: **цвета — в CSS, метаданные — в JavaScript**. React-компоненту
(переключателю тем) нужен список тем на языке JavaScript; браузеру нужны цвета
на языке CSS. Никакого дублирования: имя темы хранится один раз в реестре,
цвета — один раз в CSS.

Файл `registry.ts` **изоморфный**: он не использует ничего серверного,
поэтому его читают и серверный layout, и клиентский переключатель.

## 6. Как тема попадает на страницу

Полный путь — от клика до нового цвета. Это самая практичная часть главы,
потому что здесь видно, как связаны React, CSS и HTTP-cookie.

### Смена темы в текущей сессии

```
1. Пользователь жмёт тему в боковой панели
      └─ ThemeSwitcher: setActiveTheme(newTheme)

2. useEffect синхронизирует состояние с внешним миром
      ├─ document.documentElement.dataset.theme = newTheme   ← мгновенно
      └─ document.cookie = "orpheus_theme=newTheme; …"       ← на будущее

3. Браузер видит новый атрибут <html data-theme="mytheme">
      └─ CSS-переменные пересчитываются
      └─ утилиты (text-ink, bg-surface…) получают новые значения
      └─ НИ ОДИН React-компонент не перерисовывается
```

Смена мгновенная и не зависит от размера списка треков: React в ней
не участвует вообще.

### Почему работа с DOM — в useEffect, а не в обработчике клика

Соблазнительно сделать всё прямо в `onClick`. Но изменение `document` — это
работа с **внешней по отношению к React** системой. Правило React: синхронизация
с внешним миром живёт в `useEffect`, а обработчики событий только меняют
состояние.

Плюсы конкретно здесь:

* одно место, где меняется DOM — легко найти при отладке;
* если тему поменяет другой код, оформление применится автоматически;
* линтер React Compiler (`react-hooks/immutability`) запрещает мутировать
  внешние объекты в теле компонента и в обработчиках — и это справедливо.

### Сохранение между загрузками: почему cookie, а не localStorage

Это ключевое решение. Страница рендерится на **сервере**, и сервер должен
сразу вставить правильный `data-theme` в HTML.

`localStorage` серверу недоступен — это API браузера. Если хранить тему там,
получится:

```
сервер отдаёт тему по умолчанию
    ↓
браузер показывает НЕПРАВИЛЬНЫЕ цвета
    ↓
выполняется JavaScript, читает localStorage
    ↓
тема переключается
```

Пользователь видит **вспышку чужого оформления** (FOUC — flash of unstyled
content). А если React успеет отрисовать разметку до переключения — ещё
и ошибку гидратации.

Cookie приходит на сервер вместе с запросом:

```ts
// src/app/layout.tsx
const cookieStore = await cookies();
const themeId = resolveThemeId(cookieStore.get(THEME_COOKIE)?.value);

return <html data-theme={themeId} …>
```

Сервер рендерит нужную тему сразу — вспышки нет.

> **Правило на будущее:** всё, что влияет на серверный рендеринг, храни
> в cookie, а не в localStorage. В localStorage — только то, что нужно
> исключительно браузеру (например, громкость плеера).

### Что делает `resolveThemeId`

Значение cookie — это **пользовательский ввод**, то есть недоверенные данные.
Пользователь может вручную поставить туда что угодно. Функция проверяет,
что значение — идентификатор известной темы, иначе возвращает тему
по умолчанию:

```ts
export function resolveThemeId(value: unknown): ThemeId {
  return isThemeId(value) ? value : DEFAULT_THEME;
}
```

Проверено: `Cookie: orpheus_theme=zzz-hack` → сервер отдаёт `aegean`.
Приложение не должно падать из-за мусора в cookie.

## 7. Орнамент: меандр без единой картинки

Меандр (греческий ключ) — непрерывная линия, складывающаяся в спирали.
Самый узнаваемый орнамент античности; им украшали фризы храмов.

Реализован классом `.motif-meander`:

```css
.motif-meander {
  height: 12px;
  background-color: currentColor;          /* цвет из класса text-* */
  mask-image: url("data:image/svg+xml,…"); /* SVG-контур = трафарет */
  mask-repeat: repeat-x;
  mask-size: 12px 12px;
}
```

Три решения, которые здесь стоит разобрать.

### Почему маска, а не картинка

Обычная картинка имела бы **зашитый цвет**. В теме «Гибсон» орнамент остался
бы золотым — и это выглядело бы чужеродно.

`mask-image` использует SVG как **трафарет по прозрачности**, а цвет берётся
из `background-color: currentColor`. То есть родительский класс `text-accent`
красит орнамент в цвет акцента текущей темы. Одна плитка — три темы.

### Почему SVG вшит в CSS как data-URI

Лишний файл = лишний HTTP-запрос. SVG размером 200 байт выгоднее держать прямо
в стилях. При этом он остаётся вектором: масштабируется без потерь и не мылится
на экранах с высокой плотностью.

### Почему линия не рвётся на стыках

Плитка повторяется каждые 12 пикселей (`mask-repeat: repeat-x`). Контур
заканчивается на правом краю плитки (`x=12`) ровно на той высоте (`y=11`),
где начинается следующая плитка (`x=0`). Поэтому горизонтальная линия
выглядит непрерывной.

Это неочевидная деталь: если бы контур заканчивался на другой высоте,
на каждом стыке был бы виден разрыв.

### Дорический фриз

Второй орнамент, `.motif-frieze`, сделан **вообще без SVG** — на двух
градиентах. Он изображает фриз древнегреческого храма: чередование триглифов
(трёх вертикальных выступов) и метоп (гладких плит).

```css
background-image:
  /* верхний и нижний «рельсы» */
  linear-gradient(to bottom, var(--color-line-strong) 0 1px, transparent 1px 6px, var(--color-line-strong) 6px 7px),
  /* триглифы */
  repeating-linear-gradient(to right, …);
```

## 8. ЭЛТ-монитор: полосы развёртки

Самая узнаваемая «хакерская» деталь. Реализована **одним псевдоэлементом**,
без единого лишнего DOM-узла:

```css
body::after {
  content: "";
  position: fixed;
  inset: 0;
  pointer-events: none;   /* ← КРИТИЧНО */
  z-index: 50;
  background-image:
    repeating-linear-gradient(to bottom, …),   /* полосы развёртки */
    radial-gradient(ellipse at center, …);     /* виньетка */
  animation: scanline-drift 0.6s linear infinite;
}
```

Что здесь важно:

* **`pointer-events: none` обязателен.** Без него невидимый слой перехватит
  все клики, и ни одна кнопка не нажмётся. Классическая ошибка №1 при работе
  с полноэкранными оверлеями.
* **Плотность полос приходит из темы** через `--scanline-alpha`. У «Гибсона»
  она выше (0.22), у «Эгейского моря» ниже (0.16) — мрамор всё-таки не
  люминофор.
* **`repeating-linear-gradient` вместо текстуры.** Ноль запросов к сети,
  бесконечная чёткость.
* **`prefers-reduced-motion`** полностью отключает анимацию. Для людей
  с эпилепсией, мигренью или вестибулярными расстройствами мерцание
  физически болезненно. Это требование доступности, а не вежливость.

## 9. Шрифт: как не ошибиться с выбором

Требований к шрифту было три, и они конфликтовали:

1. **моноширинный** — обязательное условие терминальной эстетики;
2. **кириллица** — интерфейс на русском;
3. **греческий** — название ΟΡΦΕΥΣ и подписи тем.

Первым кандидатом был IBM Plex Mono. Но в наборе Google Fonts у него
**нет греческого сабсета**:

```
subsets?: 'cyrillic' | 'cyrillic-ext' | 'latin' | 'latin-ext' | 'vietnamese'
```

Греческие буквы отрисовались бы запасным системным шрифтом — другим
по ширине и начертанию, и строка «поехала» бы.

Выбран **Fira Mono**: у него есть всё сразу —

```
subsets: cyrillic, cyrillic-ext, greek, greek-ext, latin, latin-ext
```

**Мораль:** прежде чем выбирать шрифт «по красоте», проверь в типах `next/font`,
какие subset-ы он реально поддерживает. Узнать можно так:

```bash
grep -A2 "declare function IBM_Plex_Mono" \
  node_modules/next/dist/compiled/@next/font/dist/google/index.d.ts
```

### Что даёт next/font

```tsx
const terminalMono = Fira_Mono({
  variable: "--font-terminal",   // → CSS-переменная
  subsets: ["latin", "cyrillic", "greek"],
  weight: ["400", "500", "700"],
  display: "swap",
});
```

* шрифт скачивается **во время сборки** и раздаётся со своего домена —
  нет запроса к `fonts.googleapis.com` (быстрее и приватнее);
* `display: swap` плюс метрики шрифта убирают «прыжок» текста при загрузке;
* если Google Fonts недоступен, сборка упадёт сразу — ты узнаешь об этом
  в момент сборки, а не от пользователя с поехавшей вёрсткой.

> **На будущее:** при сборке Docker-образа без доступа в интернет
> `next/font/google` станет проблемой. Решение — скачать шрифт локально
> и использовать `next/font/local`.

## 10. Доступность: то, что нельзя откладывать

В проекте доступность встроена в компоненты, а не добавлена «потом».

| Приём | Где | Зачем |
| --- | --- | --- |
| `aria-label` на иконочных кнопках | `PlayerBar`, `FavoriteButton` | иначе скринридер скажет просто «кнопка» |
| `aria-pressed` на переключателях | избранное, shuffle, repeat | сообщает состояние |
| `aria-checked` + `role="radio"` | переключатель тем | это группа взаимоисключающих вариантов |
| `role="alert"` на ошибках | `PlayerBar`, формы | скринридер прочитает **немедленно** |
| `role="button"` + `tabIndex` + `onKeyDown` | строки списка треков | строка работает с клавиатуры, а не только мышью |
| `aria-current="page"` | навигация | «ты сейчас здесь» |
| `aria-valuetext` у ползунка | `SeekBar` | вместо «73.4» скажет «1:13 из 5:20» |
| `aria-hidden` на орнаментах и ASCII-графике | `motif-meander`, `<pre>` | чтобы не читал мусор |
| Различие состояний **формой**, а не только цветом | тема, избранное | дальтонизм |
| `prefers-reduced-motion` | `globals.css` | отключение мерцания |
| Видимый фокус `:focus-visible` | везде | пользователь видит, где он находится |

**Проверка за десять секунд:** отложи мышь, нажми `Tab` и пройди весь интерфейс
только клавиатурой. Если застрял или не видно, где ты находишься — это баг.

## 11. Как перенести стиль на сайт-резюме

Сайт-резюме с портфолио у тебя в планах, и стиль спроектирован переносимым.

### Вариант А: скопировать файлы (для начала — нормально)

Забрать `globals.css` плюс папку `src/themes/` целиком, выкинуть классы,
относящиеся к плееру (`.track-row`). Пятнадцать минут — и сайт-резюме уже
в теме.

Минус: две копии стилей. Поменяешь цвет в одном проекте — забудешь в другом.

### Вариант Б: вынести в общий пакет (правильно)

Если проектов станет три:

```
packages/
  hackers-greek-ui/
    src/
      tokens.css       блок @theme с ролями
      components.css   term-panel, term-btn, term-input, motif-meander…
      themes/          aegean.css, oracle.css, gibson.css
      registry.ts      реестр тем
      fonts.ts         настройка next/font
```

Подключение в любом проекте:

```css
@import "@hackers-greek-ui/tokens.css";
@import "@hackers-greek-ui/components.css";
```

Локальные пакеты в Bun настраиваются через `workspaces` в корневом
`package.json`. Один раз настроить — работает для всех проектов.

**Когда переходить на вариант Б:** при третьем проекте или когда правки
стилей станут регулярными. До этого вариант А честнее.

### Вариант В: встроить плеер в сайт-резюме

В ТЗ сказано верно: сначала плеер — самостоятельная программа, потом решаем,
как встроить. Плеер к этому готов:

* вся логика — в `src/components/player/`, и она не зависит от библиотеки:
  нужны только `TrackDTO` и API-эндпоинты;
* `PlayerBar` рендерится где угодно, если обернуть в `PlayerProvider`;
* панель плеера — обычный компонент, а не отдельная страница.

Что понадобится:

1. **Общий источник данных.** Варианты: тот же SQLite-файл (если проекты
   рядом), HTTP-запросы к API плеера (`/api/tracks`) или заранее
   сгенерированный JSON.
2. **Доступ к аудио из другого домена.** Понадобится CORS либо общий домен
   за прокси. В `src/lib/stream-url.ts` сейчас жёстко зашито
   `/api/tracks/{id}/stream` — для встраивания туда нужно добавить базовый
   адрес из переменной окружения (правка на пять строк).
3. **Скрыть лишнее.** Громкость и repeat можно убрать в «раскрывающуюся»
   часть, оставив только транспорт.

**Отдельная идея, которая выглядит сильно:** показывать на сайте-резюме
**реальную статистику из плеера** — «топ-5 треков по прослушиваниям за месяц».
Запрос `listTopTracks` уже написан (`src/lib/db/history-queries.ts`), данные
живые. Для рекрутера это выглядит совсем иначе, чем «человек сделал проект»:
«человек сделал продукт и пользуется им каждый день».

## 12. Чего избегать

| Антипаттерн | Почему плохо |
| --- | --- |
| Хардкод цвета в компоненте (`text-[#e8b53f]`) | тема перестанет на него влиять |
| Использовать цвет рамки для текста | контраст почти наверняка провалится (у нас было 1.3:1) |
| Проверять контраст «на глаз» | глаз адаптируется и перестаёт замечать проблему |
| Один цвет на все роли | пропадает визуальная иерархия, «что важно» непонятно |
| Хранить тему в localStorage | вспышка чужого оформления плюс риск ошибки гидратации |
| Мерцание ярче, чем в фильме | быстро утомляет и опасно для части людей |
| Много светящегося текста (`glow` везде) | свечение **снижает** читаемость |
| Анимации дольше 150 мс | терминал должен отзываться мгновенно |
| Забыть `pointer-events: none` на оверлее | интерфейс перестаёт нажиматься |
| Различать состояния только цветом | недоступно при дальтонизме |
| Свой «велосипед» вместо `<input type="range">` | теряются клавиатура, тач и доступность |

## 13. Шпаргалка

| Нужно | Как |
| --- | --- |

| Кнопка | `term-btn` (+ `term-btn-danger`, `term-btn-active`) |
| Поле ввода | `term-input` |
| Заголовок раздела | `term-title` |
| Орнамент-разделитель | `<div className="motif-meander text-accent" aria-hidden="true" />` |
| ASCII-рисунок | `<pre aria-hidden>` + `leading-tight` |
| Обрезать длинный текст | `min-w-0` на родителе + `truncate` на тексте |
